# ZombieBuddy loading and patching

Primary binary-derived references are under `reference/zombiebuddy/decompiled/me/zed_0xff/zombie_buddy/`. Corresponding shipped source is under `reference/zombiebuddy/workshop/java/src/main/java/me/zed_0xff/zombie_buddy/`. The installed JAR, not that source tree, defines runtime behavior.

1. The installed launcher passes `-agentlib:zbNative`. Shipped `c/windows/zbNative.c::Agent_OnLoad` loads the JRE's `instrument.dll`, delegates its `Agent_OnLoad` using `ZombieBuddy.jar` as agent options, and supports applying a pending `.new` JAR. The installed native DLL matches the Workshop DLL; its shipped C source is supplementary, not a proof of a reproducible native build.
2. The installed JAR manifest declares `Premain-Class: me.zed_0xff.zombie_buddy.Agent`, class redefinition and retransformation. `Agent.premain(String, Instrumentation)` stores instrumentation, applies early loader patches, and invokes `Loader.preloadMods()`.
3. `patches.Patch_ZomboidFileSystem` intercepts game mod loading. `Loader.loadMods(ArrayList<String>)` resolves Java mod metadata, dependency/order information and approval/signature state. `JavaModInfo` reads `javaJarFile`, `javaPkgName`, and required versions. PZ3D's installed descriptor points to `media/java/client/PZ3D-0.2.2.jar`, package `com.pavelvoronin.pz3d`, requiring ZombieBuddy >=2.3.2.
4. `Loader.addJarToClasspath(Path,String,String)` calls `Instrumentation.appendToSystemClassLoaderSearch(JarFile)`. `loadJar(...,Phase)` invokes `ApplyPatchesFromPackage(...)`. PREMAIN uses `<package>.PreMain.premain(String[])`; the normal phase uses `<package>.Main.main(String[])`. The package's first phase also runs `PatchEngine.applyPatches(String,ClassLoader)`.
5. `PatchEngine.collectPatches` discovers annotations via ClassGraph. `PatchTransformer.transformPatchClass` rewrites ZombieBuddy's annotation descriptors into Byte Buddy Advice/delegation equivalents. `@Patch.OnEnter(skipOn=true)` maps to skipping the target on a non-default advice return; `@Patch.Return(readOnly=false)` can replace results. Methods can be selected by name, explicit signatures, or inferred arguments; `strictMatch` matters for overloads.
6. `PatchEngine.applyPatches` installs Byte Buddy AgentBuilder transforms using `RETRANSFORMATION`, handles already loaded classes, and warms requested targets. It excludes patch targets starting with `me.zed_0xff.`; it does **not** impose a vanilla-only `zombie.*` target restriction. Thus targeting `com.pavelvoronin.pz3d.*` is plausible. Multiple delegation patches targeting the same method can conflict; advice order across mods is not a stable extension contract.
7. `Exposer` supplies annotated Lua bindings. PZ3D's `@Exposer.LuaClass(name="PZ3D") Main` is exposed to the copied client Lua scripts.

This is bytecode instrumentation inside the game's JVM, not replacement of Java class files on disk. Reflection can reach private/package members in these unnamed-module classes in principle, but access and classloader identity must be verified. Reflection cannot split one method's instruction stream into prepare/draw sections, cannot make a forward vector represent roll, and should not be used to rewrite final captured fields as the primary design.

PZ3D's `Main.main(String[])` verifies patch target classes, installs `ChunkProbe` instrumentation, loads user settings and visual extensions, and initializes diagnostics, sky, and shader caches. Its 170 declared `Patches` targets all exist in the installed vanilla archive. [Full inventory and candidate JVM descriptors](patch-inventory.md) is generated from the installed binaries. `ChunkProbe.install()` is additional direct instrumentation, so the 170 annotations are not an exhaustive count of every transformed call site.

The installed loader has actual JAR signature/approval policy. A future newly built add-on must use its supported development/approval flow; this phase neither changed that policy nor installed an unsigned JAR. Source docs `workshop/doc/ModdingGuide.md` and `ModSigning.md` are retained for that future phase.
